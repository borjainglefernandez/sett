Design tenets

Four principles every screen and feature is measured against.

1 · Rest runs itself

Finishing a set is starting the rest timer. No extra tap, ever. Per-exercise defaults (90 s compounds, 60 s isolation, editable inline), a pinned countdown capsule with −15/+15, 3-2-1 haptic ticks, and the countdown lives on the Dynamic Island and lock screen so the phone sits face-up on the bench.

2 · Zero-friction tracking

The app already knows what you're about to lift — you just confirm it. Every set pre-fills from last week's same set (or the routine plan); repeating it is one tap of the checkmark. The iPhone banner is a full logging surface: when rest ends, a "Log set" action on the notification commits the pre-filled set without unlocking the phone. Bodyweight logs in one thumb from Home.

3 · Animate everything (except input)

Every state change moves: numbers roll, auras breathe, charts draw in, badges stamp, tabs bounce. Two hard rules survive: nothing animates between your tap and the set being saved, and every effect has a Reduce Motion fallback. The motion grammar lives in §12.

4 · The power level is the protagonist

Not a widget beside a workout list — the organizing principle. Logged sets spawn power that visibly flies into it, every gauge counts toward it, ceremonies stage it, and it owns the gold hue exclusively. Numbers are events, not labels. Full spec: the Dark Chamber, §12.

System architecture

The phone is the source of truth; the server is backup, integration hub, and weekly brain. The app works forever with zero connectivity — sync is a background courtesy.

  • Local-first: every feature — logging, nets, charts, badges, power level — computes from the on-device store. No spinner ever blocks a set.
  • One sync pipe: workouts flow up; sleep data and AI digests flow down through the same cursor-based pull. No special-case endpoints.
  • Server-side only where it must be: Apple token verification, invite enforcement, Oura OAuth + daily pulls, weekly Claude digests, backups.
03

iOS client

Stack

  • iOS 26 minimum, Swift 6 strict concurrency (default MainActor), Xcode 26
  • 100% SwiftUI, @Observable feature stores — no Combine, no TCA, no third-party architecture
  • TabView + typed NavigationStack routes; active workout is a fullScreenCover that survives tab switches
  • Deep links sett://… from notifications and the Oura OAuth return
  • ActivityKit rest-timer Live Activity + actionable notifications: the "Log set" UNNotificationAction commits the pre-filled set via a background handler — no unlock, no app launch

Two-module split

  • Sett (app target): views, theme, notifications, widgets
  • SettCore (local SPM package, zero SwiftUI): models, ProgressEngine, ProgressionEngine, SyncActor, Foundation Models commentary, seed catalog
  • Swift Testing suites run against SettCore in seconds — engine, sync, and badge predicates are the test surface (v1 had zero tests)
  • App Group shares cached power level / goal ring with WidgetKit + Live Activity

Persistence: SwiftData

On an iOS 26-only target SwiftData is third-generation and mature; @Query/@Model erase a glue layer for a solo dev, and the History API provides the change tracking the sync engine needs. One person's lifetime of sets is tens of thousands of rows — far below any scale where GRDB's raw SQL would matter. Build gotcha (learned in practice): never declare an inline #Predicate inside a @Query property — it times out the Swift 6 type-checker; configure queries in an explicit init().

Data model

Every synced model shares four conventions: client-generated UUID identity, updatedAt for last-writer-wins, deletedAt soft-delete tombstones, and a needsPush dirty flag.

Canonical rules that fix v1's flaws
  • Weight = integer grams everywhere (client, wire, Postgres). 0.25 kg = 250 g exactly; 2.5 lb = 1134 g and round-trips perfectly. Never a float. (v1: integer lbs only.)
  • Every set has completedAt — timestamps drive pairing, buckets, and badges. (v1: none.)
  • Workouts reference routines by loose UUID + name snapshot, never a live relationship — deleting a routine can never damage history. (v1: shared live objects.)
  • Badges are a code-defined key catalog; only BadgeAward rows persist. (v1: free-text strings holding SF Symbol names.)
  • Units are a display setting (lb/kg, plate increment). (v1: "lbs" hardcoded.)

05

Net-progress engine (user story 3)

Pure functions in ProgressEngine over value-type set samples. No stored aggregates — recompute on demand (<10 ms at this scale), memoized per screen, invalidated on save.

  • Identity = exercise UUID, never name or insertion order. Renames keep history.
  • Buckets = ISO week / calendar month / year in the user's timezone, Monday first by default.
  • Net = this bucket − the immediately preceding calendar bucket, for total reps and total volume (weight × reps). An empty previous bucket shows NEW rather than a misleading +everything; a regression shows honestly negative.
  • Live per-set deltas: reference = your most recent finished workout containing that exercise; sets pair by completedAt order. Autofill pre-populates set i from reference set i, unless a routine plan specifies targets (plan wins).
  • e1RM = Epley with reps capped at 12: w × (1 + min(r,12)/30) — monotonic, finite, un-fakeable with 50-rep bar work. Gold PR dots on charts come from verified bests (§11).
06

Sync protocol

Single user per account, multi-device rare ⇒ per-record last-writer-wins. No CRDTs. Pull-from-zero doubles as device restore, so there is no separate backup format.

Push · POST /v1/sync/push

Client sends all needsPush rows (≤500/batch) in FK-safe order. Server upserts iff incoming updated_at is newer, answers applied | stale per row. Idempotent — retry blindly. Active workouts never push.

Pull · GET /v1/sync/pull?since=<seq>

One global sync_seq sequence, bumped on every insert/update across all synced tables (tombstones included). Client applies in order — local unpushed edits win — and persists the cursor. Sleep days and AI digests arrive through this same stream.

Triggers: workout finished (debounced 5 s) · app foregrounded · connectivity regained · one overnight BGAppRefreshTask that lands fresh Oura data and digests before morning. Failures back off silently; the gym is never blocked. Auth failures degrade to a quiet "re-login" flag in Settings.

08

Auth & invite-only

1

Client sends the Sign in with Apple identityToken (+ nonce, device id, invite code on first login) to POST /v1/auth/apple. On first authorization it also forwards the email Apple provides once — v1 discarded it forever.

2

Server verifies RS256 against Apple's JWKS (cached 24 h), checks issuer, audience (bundle ID), expiry, nonce; extracts the stable sub.

3

Invite enforcement: new-user creation and invite redemption are one atomic transaction — UPDATE invites … WHERE code=$c AND redeemed_by IS NULL AND expires_at > now() RETURNING code. Zero rows ⇒ 403, no account. One code, one account, no open registration path anywhere.

4

Sessions: 1-hour HS256 access JWT + per-device 90-day opaque refresh token, stored hashed, rotated on every use. Reuse of a rotated token revokes the device (theft signal) and the client silently re-runs Sign in with Apple.

09

Oura integration

  • OAuth2 code flow (free API v2 app): the client opens /v1/oura/connect's authorize URL in ASWebAuthenticationSession; the server callback exchanges the code, Fernet-encrypts tokens, and bounces to sett://oura/connected. A personal-access-token fallback (POST /v1/oura/pat) works before the OAuth app is even registered.
  • Daily pull (worker, 09:30 UTC + 15:30 retry sweep): daily_sleep, sleep, and daily_readiness over a trailing 7-day window — late-syncing rings self-heal via upsert. Bumps sync_seq; phones get it on next pull.
  • Token refresh proactive (1 h before expiry) and reactive (on 401); repeated failure flips status to error so the app prompts a reconnect.
  • Rate limits: 10 users × 3 calls/day vs Oura's 5,000 req/5 min — four orders of magnitude of headroom.

AI insights — hybrid

Instant · on-device

Foundation Models (iOS 26, A17 Pro+) generates 2–3 sentences of post-workout commentary in Vego's voice — the proud-rival persona. Guided generation (@Generable) constrains shape; the prompt contains structured facts only, never raw user text; 10-second timeout. Unsupported devices get a deterministic template over the same facts — the screen looks identical, only the source field differs.

Monday-morning worker job assembles ≤6K tokens of pre-computed rollups — per-exercise weekly nets (8 weeks), goal progress, sleep-per-workout pairing table — and calls claude-haiku-4-5 once per user. Gamification — the Hypertrophic Time Chamber (hypertrophy × Hyperbolic Time Chamber)

Power level, XP, and badges are derived state, always recomputable from raw training data (constants in a versioned progression_config.json). You cannot farm what is recomputed.

Power Level

e1RM(set) = weightLb × (1 + min(reps, 12) / 30)          // rep-capped Epley

SS = Σ over 6 muscle groups of best verified e1RM, trailing 90 days
WVL = mean weekly effective volume-load, trailing 28 days
CM = 1 + 0.05 × min(streakWeeks, 10)                      // 1.00 – 1.50

PL = round( (4 × SS + 8 × √WVL) × CM )
ScenarioSSVolume termCMPL
Week 1 — new user, 2 workouts4754901.002,390
Month ~5 — honest 4×/week, 8-week streak1,2251,6401.409,156 — over the threshold, earned
Cheater — 7 junk sessions/day, empty-bar 100-rep setsfiltered before the math ever sees itbarely moves

Anti-cheese, layered at the set level: only "effective" sets count (reps 1–30, ≥40% of your e1RM once history exists, first 6 sets per exercise, first 30 per workout, first qualifying workout per day); √-compression on volume; PR jumps >15% are provisional until repeated on another day ("the Scanner needs a second scan"); one workout of XP per day at full value, max 6 XP days per rolling 7, 300 XP/day cap. Editing or deleting workouts recomputes the whole ledger.

Rested Bonus (v3, new mechanic): full rest days accrue a recovered XP segment — rendered as a gold band ahead of the cyan fill on the power gauge with a notch marker (the WoW rested-XP grammar). The first workout after a full rest day earns 1.25× workout XP and visibly burns the gold segment first. Rest becomes a game resource instead of guilt — and it compounds the existing rest-day anti-cheese rather than fighting it. (Engine change: flag for ProgressionEngine + config.)

Where the hype happens

  • The Scan Ritual (every summary — v3, replaces the plain Power Scan): the screen vignettes down to scan-state; digits scramble and resolve left-to-right with accelerating tick haptics; the count-up hit-stops for ~100 ms at every +100 milestone then resumes faster; the final total slams in with a heavy haptic and a 2-px screen shake. Crossing a tier threshold or PR ceiling plays a glass-crack overlay — the old ceiling number fractures, light leaks through the fissures, and the new number punches through. Vego's one-liner below.
  • PR aura burst (in-workout): gold ring + crit-scale floating text off the set row (2× scale, settle bounce). Provisional PRs get a dashed cyan ring; the burst fires on verification — "Confirmed. It was real."
  • Transformation Ceremony (rare by design): full-screen takeover — the old tier card fractures from center, shards fall, the new tier is revealed beneath in a vertical light column, longer for rarer tiers. Never mid-workout — queued to the summary.
  • Vexeth form reveal (whenever your PL catches his script): his card cracks, the screen dims to near-black, and the silhouette of the next form fades in under a crimson glow — "You've forced my hand." The only celebration in the app that runs red.
  • Weekly Power Scan (Sunday 18:00): PL sparkline, tonnage delta, streak status, and Zia's sleep line from the Claude digest. The retention loop.
  • All: ≤4 s, tap-to-skip, silent, full Reduce Motion fallbacks (scramble → direct set, crack → crossfade). Goals pay flat completion bonuses and never feed the consistency multiplier — no event is ever paid twice.

Friends & the Time Chamber Finder

Invite-only means everyone in the database is someone you actually train with. That makes a social layer cheap to build and high-trust by default — and it makes crowd-sourced gym data (the only reliable source of day-pass prices anywhere) actually work at ten users.

Power Rankings — track your friends' progress

  • Explicit, mutual friendships via short friend codes (auto-suggested from the invite lineage). POST /v1/friends/invite · /accept · GET /v1/friends.
  • What friends see — a privacy-filtered snapshot, never raw data: power level + peak, transformation tier, streak weeks, workouts this week, latest badges, last trained day. Sets, weights, bodyweight, and notes stay private; an opt-in "share PRs" toggle adds top e1RM per lift.
  • UX: the Power tab gains a Power Rankings card — friends sorted by PL with tier auras, streak flames, and a one-tap ⚡ Respect reaction (delivered on their next open; APNs deferred). Vexeth stays in the list as the house villain everyone shares.
  • Weekly digest hook: "You out-lifted Marcos by 2,100 lb this week. He doesn't know yet."
  • No XP from social, ever — friends are motivation, not currency.

Log where you trained

  • New synced Gym model; workouts carry gymID? + name snapshot — loose-reference pattern, so deleting a gym never touches history.
  • Auto-tag, zero friction: one when-in-use location fix at workout start; within 150 m of a saved gym it tags silently, otherwise a "New chamber here?" chip. Never blocks logging, works offline.
  • Stats: workouts per gym and a home/away split in Progress — vacation training counts toward streaks and goals like any other.

Time Chamber Finder — gyms while traveling

  • Discovery is free and native: MKLocalSearch (MapKit) finds gyms near the map region on-device — no API key, no ToS drama. Results render as chamber pins.
  • Ratings enrichment: a backend proxy to Google Places (free tier, quota-capped) adds star ratings on tap, caching only place_id per ToS; deep-links to the full Maps place page.
  • Chamber Logs — the community price layer: no API knows gym day-pass prices, so sett users are the source. After a workout: optional 10-second log — stars, day-pass price paid, one-liner. Aggregated gym-level only, never who trained where or when.
  • Cost: $0. MapKit free, Places inside free tier, Chamber Logs in our Postgres (gyms + gym_logs, GET /v1/gyms/nearby).

Reconciliation log

The four specialist designs were produced independently, then cross-checked. Conflicts found and resolved:

Tabs: Home / Train / Progress / Power
UX owns navigation; client's typed-route architecture is unaffected. Profile-tab features moved to Power + a Settings sheet.
Tier names: Base → Kindled → Ascendant → Radiant → Zenith
Gamification owns the ladder and its badge-gated thresholds.
Weight canonical unit: integer grams end-to-end
Client, wire format, and Postgres (weight_g int). Gamification's lb-equivalent math is a pure conversion at compute time.
Power level is derived, never summed from badge deltas
The windowed formula wins; SaiyanState is a display cache for widgets.
Goal kinds unified to frequency · pr_target · volume_target
Gamification's taxonomy wins because the anti-double-reward XP rules are defined per kind.
Per-set routine planning wins over per-exercise
Backend gains a planned_sets table mirroring the client's PlannedSet.
One e1RM rule: Epley with reps capped at 12
Sets with 1–30 reps eligible; the cap defangs high-rep inflation.
One AI persona: Vego
The on-device Foundation Models prompt and the server Claude digest share the proud-rival voice.
Badges are client-authoritative in v1
Computed on device, pushed as badge_events; the server-side Python mirror is deferred to v1.1.
Live Activity + widgets in v1 scope
Requires an App Group and a WidgetKit extension from day one.
v3 (user feedback, July 7): the Dark Chamber replaces Apple-neutral theming
Permanently dark, warm near-black, vignette + grime + etched borders; gold becomes PL-exclusive; every stock progress bar becomes a Ki Gauge; numbers become events (scan ritual, combat text, screen-crack). The v2 "semantic system backgrounds" stance is retired.

Open risks

  • Character artwork (23 flat-vector illustrations) is the one asset code can't produce. Art routes through a swappable asset pack keyed by characterKey + tier, so a private personal build can carry any skin without touching the distributed app.
  • Foundation Models on real hardware — latency and guardrail behavior need a device spike; the template fallback makes it non-blocking.
  • Oura OAuth app registration must exist before the callback URL is final; the PAT fallback works from day one.
  • Badge revocation UX — deleting a workout recomputes the ledger; show an "evidence removed" state rather than silent disappearance.
  • No APNs in v1 — Respect reactions arrive on next app open; push infra is a deliberate v2 line item.
  • Google Places ToS permits caching place_id only — the Finder proxy re-fetches ratings per view; Chamber Logs carry the persistent layer.
  • v3 restraint risk — the Dark Chamber's failure mode is Dokkan-lobby noise. Guardrails: one quest surface, big motion never for small events, ornament budgeted by rank, text always on flat fills at 4.5:1.
